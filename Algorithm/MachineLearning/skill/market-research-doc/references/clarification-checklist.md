# 澄清清单

目标：在动笔前锁定决策、范围和证据边界，避免“写得很完整但答非所问”。

## 一次性提问（5-8 个）

1. **决策与读者**：这次调研支持什么决策？谁拍板？何时使用？本次是“多方案选型比较”，还是“基于指定基础方案写总体落地方案”？怎样算成功，哪些结果不可接受？
2. **主题与边界**：调研对象是什么？包含和不包含哪些能力、组织、产品、仓库或时间范围？
3. **技术与合规**：部署形态、规模、现有技术栈、SLA、峰值、延迟、数据边界和合规要求是什么？
4. **现状与材料**：华泰（或用户指定组织）当前的系统、流程、指标和痛点是什么？能提供哪些内部材料，由谁负责补充？如需公开分享，哪些内部事实已获准披露？
5. **实践对象**：用户是否点名厂商、产品或开源项目？未点名时，是否采用 AI Code Review 默认六簇？
6. **输出要求**：交付路径、篇幅、Markdown/Word/PPT、是否需要预览可见图片、截止时间是什么？
7. **约束与否决项**：预算、国产化、现有供应商、团队技能、必须兼容的系统，以及会直接否决方案的条件是什么？

## 用户说“你先写 / 按你的理解写”

- 在正文 1.3 节增加“假设与待确认项”，不新增一级章节。
- 对每个假设写明依赖它的结论；假设推翻时，哪些结论需要重做。
- 缺失的内部数据统一标注 `待补充` 和责任人，不用未说明的行业均值替代。

## 完成标准

以下事项都有明确答复，或已作为假设写入 1.3 节：

- 主题、决策、读者、成功/否决标准和第四章模式
- 范围、部署形态、规模与技术约束
- 华泰现状材料，或“暂无，先按公开信息写”
- 用户点名的实践对象，或采用默认六簇的决定
- 输出路径、格式、篇幅、图片要求、时间，以及公开分享时的内部信息授权边界

来源清单确认属于下一阶段 Gate，不并入本阶段；未提交并确认来源清单前不开始正文。
