# 挑选待打印照片并生成日期/水印版本

处理源文件夹及其子文件夹中的照片，在用户确认后生成三层结果：`01_selected` 保存选中的原始照片，`02_name_with_date` 保存日期命名副本，`03_watermark` 保存最终水印副本。不得再创建或使用 `待打印`、`final` 等旧目录名。

目标是留下少量、清晰、可打印、能还原重要事件的照片，而不是机械地按文件名或时间复制照片。

本 skill 的可执行辅助脚本位于 `scripts/`（以本 `SKILL.md` 所在目录为基准）：

- `scripts/changeImgNameByTime.py`：读取 EXIF 拍摄日期（没有 EXIF 时回退到文件修改时间），在工作目录内生成 `dst_copied_name_with_date`，输出名以 `YYYY-MM-DD` 开头；HEIC/HEIF 会转换为 JPG；含中文的工作副本文件名可能先被改为 UUID。该脚本只能对临时工作副本运行，不能对源目录或正式输出目录运行。
- `scripts/addTimestampWatermarktoImgs.py`：读取日期命名目录，在其中生成 `dst`，把日期文字写入图片左下方；它会直接执行模块级入口，必须从日期命名目录的临时副本中运行。水印脚本支持的格式不包含 HEIC/HEIF，因此 HEIC/HEIF 必须先由上一步转换为 JPG。
- 运行环境要求 Python 3.10，以及 `requirement.txt` 中的 Pillow、opencv-python、pillow-heif。脚本不联网、不上传照片。

## 源目录与选片模式

开始处理前必须先询问用户要处理的源文件夹，并递归统计其图片文件和直接子文件夹。若源文件夹包含多个子文件夹，必须让用户二选一：

1. **一次处理全部**：把源文件夹及其所有子文件夹视为一个选片集合，统一按事件、连拍和重复关系挑选；结果平铺放入 `01_selected`。
2. **逐个子文件夹处理**：每次只处理一个直接子文件夹及其子目录。完成该子文件夹的候选筛选后，先复制到 `01_selected\<子文件夹同名目录>`，展示候选并等待用户确认；用户确认后才处理下一个子文件夹。每个子文件夹都必须单独确认，拒绝或未确认时停止该文件夹及后续文件夹的处理，并保留已确认结果。

若只有一个子文件夹，仍需询问源文件夹，但不需要询问上述模式；按该唯一子文件夹处理。若源文件夹根目录也有图片，必须明确告知用户：在“逐个子文件夹处理”模式下，根目录图片作为单独的“根目录文件”组确认，或在用户选择后并入一次处理全部模式，不能静默遗漏。

选片模式只影响选片和确认节奏，不影响后续脚本：无论选择哪种模式，所有已确认照片在日期命名前都必须从 `01_selected` 的文件和子文件夹中汇总到一个临时平铺工作目录；日期命名一次性生成平铺的 `02_name_with_date`，水印一次性生成平铺的 `03_watermark`。

## 不可违反的约束

- 只复制，不移动、删除、重命名或修改源文件；不清理源目录中的重复照片。
- 选片阶段不修图、调色、压缩、加水印或上传网络；日期重命名和水印只允许作用于临时工作副本，源照片和选片正式副本不得被脚本原地修改。
- 不覆盖输出目录已有文件。同名时使用来源子文件夹前缀；仍冲突时增加短数字后缀，并记录冲突。
- 视频（`.MOV`、`.MP4`、`.AVI` 等）不选。
- 复制必须先进入临时目录；全部文件复制成功并核对数量后，再移入正式输出目录。失败时清理临时目录，不留下半成品。
- 脚本阶段必须继续使用独立的临时工作树；不得把脚本生成的 `dst_copied_name_with_date` 或 `dst` 直接放入源目录，也不得覆盖已有目录。正式测试/交付目录统一使用三层平铺结构：`01_selected`（仅选中的原始照片）、`02_name_with_date`（日期命名副本）、`03_watermark`（最终水印副本），不再使用 `final` 文件夹。
- 每个确认闸门都必须暂停并等待用户明确确认；没有确认不得进入下一步。用户拒绝时保留当前结果供查看，并停止后续脚本。

## 选择优先级

按下面顺序判断，不要用低优先级因素推翻高优先级因素：

1. **事件代表性**：覆盖不同日期、地点、活动和人物组合。每个有意义的事件至少留一张代表照。
2. **关键仪式**：生日庆祝优先保留能看出吹蜡烛或许愿的照片；连拍中即使只有一张符合，也要保留这张作为生日代表。优先选择人物睁眼、表情自然、画面清晰的仪式照；若仪式照全部闭眼，寻找同一生日场景中睁眼的人物照，不要为了凑仪式强选明显不合格的闭眼照。
3. **人物状态**：优先笑容自然、眼神有神、正脸或有明确互动、姿态舒展的照片。人物主体应睁眼；排除呆滞、无神、走神、闭眼、明显不自然、佝偻、塌腰、猥琐或动作不雅的画面。
4. **叙事完整**：集体照、互动、旅行、生日、游戏等有故事的场景优先于孤立的物品或景色。纯景色、建筑、食物或物品照不选，除非它与人物活动共同构成不可替代的事件记录。
5. **画面质量**：排除严重模糊、明显失焦、过度压缩、截图、放大的缩略图和明显低分辨率照片。任一边小于约 1200px 或文件小于约 300KB 时谨慎判断，不仅凭文件大小淘汰。
6. **多样性**：同一人物、同一姿势、同一背景不要重复堆积；保留不同构图、互动关系和环境信息。

## 连拍与编辑版

- 文件名相邻、拍摄或修改时间相差几秒、构图高度相似的照片先归为同一连拍组，再逐张看图。
- 连拍说明场景可能重要，不能整组淘汰；每组至少保留一张最佳代表照，必要时为还原互动最多保留两张。
- `IMG_1234` 与 `IMG_E1234`，以及带 `_E`、`-编辑` 等后缀的文件，通常是同一张的原版和编辑版。必须配对比较：编辑版在曝光、色彩、裁剪、清晰度或人物状态上更适合打印时保留编辑版，否则保留原版。两版只选一张。
- 不同子文件夹中同名或构图相同的照片也要按同一事件去重；不能仅凭文件名、大小或时间下结论，必须看图确认。

## 数量与分组

- 用户指定数量时按用户数量执行。
- 未指定数量时，先统计总量和事件分组；通常每组 1~4 张、总量控制在 20~30 张以内。
- 照片很少时不要为了达到下限硬选；事件特别重要时可以超过 30 张，但要在汇报中说明原因。
- 分组可依据子文件夹、日期、地点、生日等事件线索；根目录照片也要按时间和画面内容分组。

## 执行流程（六步，三个确认闸门）

1. 询问源文件夹；统计根目录图片、直接子文件夹、递归图片数量，记录路径、文件名、格式、尺寸、大小和时间，排除视频。若有多个子文件夹，询问用户选择“全部一次处理”或“逐个子文件夹处理”。
2. 按所选模式递归列出图片，按事件、连拍和编辑版规则筛选，生成缩略图或联系表并逐张查看。
3. 复制候选并执行确认闸门 1：
   - “全部一次处理”模式：将入选照片复制到 `01_selected` 根层，核对数量、文件名、大小和可读性后，汇报候选清单、覆盖事件、生日/仪式照、HEIC 数量和冲突记录，并询问：`是否确认这些照片进入日期重命名阶段？`
   - “逐个子文件夹处理”模式：按子文件夹顺序处理，每个子文件夹完成筛选后只复制到 `01_selected\<子文件夹同名目录>`，核对该组候选并展示后询问：`是否确认本子文件夹的这些照片？确认后继续下一个子文件夹。`；只有明确确认才继续。全部子文件夹（以及用户选择纳入的根目录图片组）完成后，汇总报告整体数量和事件覆盖，并询问：`是否确认所有已确认照片进入日期重命名阶段？`
4. 确认闸门 1 通过后，将 `01_selected` 中所有已确认照片（递归读取子文件夹）复制到独立临时工作目录，并在该临时目录中平铺、处理同名冲突后执行 `scripts/changeImgNameByTime.py`（例如 `python <skill-dir>\scripts\changeImgNameByTime.py`）。脚本生成的 `dst_copied_name_with_date` 校验通过后，只把其中的文件复制到正式中间目录 `02_name_with_date`；`01_selected` 始终只保留选中的原始照片，脚本临时目录完成后清理。记录脚本日志、异常文件、EXIF/文件时间回退情况、中文名 UUID 改名和 HEIC 转 JPG 情况。核对输出数量、文件名、大小和可读性后，停止并询问：`是否确认这些日期命名后的照片进入加时间水印阶段？` **这是确认闸门 2。**
5. 用户确认后，将 `02_name_with_date` 复制到另一个独立临时水印工作目录，再运行 `scripts/addTimestampWatermarktoImgs.py`（例如 `python <skill-dir>\scripts\addTimestampWatermarktoImgs.py`）。脚本生成的 `dst` 校验通过后，只把其中的文件复制到正式输出目录 `03_watermark`；不得在 `02_name_with_date` 内直接写水印结果，也不得保留额外的 `dst` 嵌套层。核对水印输出数量、文件名、大小、可读性及水印日期文本后，停止并询问：`是否确认这些水印照片作为最终输出？` **这是确认闸门 3。**
6. 用户最终确认后，`03_watermark` 即为最终输出目录；不得再包裹 `final` 文件夹。目标已存在时停止并换用新测试/输出目录名，不覆盖旧结果。最终汇报三层目录路径、总张数、脚本异常、日期来源（EXIF/文件时间）、HEIC 转换、中文文件名变化和水印格式；保留 `01_selected`、`02_name_with_date`、`03_watermark` 供用户复核，清理脚本临时工作目录。

### 脚本执行细则

- 每次运行脚本前先确认当前工作目录和输入文件清单；禁止使用脚本默认的 `.` 指向源目录。
- 脚本路径固定为本 skill 目录下的 `scripts/changeImgNameByTime.py` 和 `scripts/addTimestampWatermarktoImgs.py`；运行时可从临时工作目录调用绝对路径或相对于 skill 目录解析的路径。
- 脚本只处理临时工作目录根层的文件，不递归读取子目录；因此运行 `changeImgNameByTime.py` 前必须把 `01_selected` 中所有已确认照片复制到临时目录根层，并用来源子文件夹前缀或短数字后缀解决同名冲突。这个平铺只发生在临时工作目录，不能改变 `01_selected` 的组织结构。
- 使用项目 Python 3.10 环境；先检查 `PIL`、`cv2` 和 `pillow_heif` 可导入。缺依赖时只报告并停止，不擅自联网安装。
- 脚本生成目录必须使用唯一临时目录名。执行成功后以文件数、相对文件名集合、字节数和逐文件可读性校验；任一校验失败，删除未发布的临时结果并报告。
- `changeImgNameByTime.py` 的日期只精确到日；它可能按脚本逻辑回退到修改时间，不能把文件系统时间误报为 EXIF 时间。
- `addTimestampWatermarktoImgs.py` 使用 OpenCV 写出图片，正式汇报中说明这是重新编码后的副本；不把水印副本当作无损原图。

## 默认确认节奏

本流程始终执行三个确认闸门，即使选片范围清楚或用户要求静默执行，也不得跳过确认。每个闸门只接受用户明确的肯定答复；模糊答复、无答复或拒绝都停止后续阶段。用户可以在任一阶段要求重新选片、放弃脚本或删除未发布的临时结果。

## 格式与隐私

- 选片阶段保留源照片格式；若源照片为 HEIC/HEIF，日期命名脚本会在临时工作副本中转换为 JPG，正式结果中记录该转换并提醒冲印店兼容性问题。源照片始终不变。
- 含人脸的照片不上传、不发送给第三方服务，只在本地查看和复制。
